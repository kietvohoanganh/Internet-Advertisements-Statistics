# Reproducibility

[Overview](../README.md) · [Methodology](methodology.md)

## Clean checkout

Use R 4.6.2, Python 3.11 and Make, then run:

```bash
make setup
make download
make run
make publish-results
make check
```

Do not copy `.venv`, R libraries, processed data or intermediate outputs between machines. `renv.lock` pins the R packages and their dependencies, including glmnet 5.2, ggplot2 4.0.4 and jsonlite 2.0.0. `.Rprofile` loads the project environment through `renv/activate.R`; `make setup` restores the locked versions without falling back to newer packages. The bootstrap is generated by renv and kept unchanged; restoring the environment rewrites it from the upstream template. [renv restoration](https://pkgs.rstudio.com/renv/reference/restore.html)

Python versions are pinned in `requirements.txt`. The local run used Python 3.11.16 and scikit-learn 1.7.2. Exact versions are also recorded in the statistical-summary provenance rows. A lockfile does not fix operating-system libraries, compilers, fonts or BLAS; cross-platform outputs may still differ numerically or visually.

The UCI download preserves `ad.data`, `ad.names` and `ad.DOCUMENTATION`. The release source MD5 is `889d28cc6f87a6f5a8c18f26b7b0c616`. Kaggle `add.csv` is also supported with the UCI dictionary; when both inputs exist, `ad.data` takes priority. Never edit the original labels or overwrite source data to improve a score.

`config.R` freezes the release seed, folds, search grids, solver budget/tolerance, bootstrap count and selection objective. This release does not introduce a new model search. Changes to analysis code or configuration require a fresh run before publication. `outputs/run_status.csv`, `run_warnings.csv`, `source_checksums.csv`, `session_info.txt` and `validation.txt` provide the generated audit trail.

## Prediction

An input row is a complete UCI feature vector, not an image file. Columns are numeric and match the `feature` column of `data/processed/feature_dictionary.csv`. Unknown values use `NA`; binary fields accept only 0, 1 or `NA`. Empty frames, duplicate names, missing columns, invalid categories and infinite values are rejected.

Create an example from the fixed historical partition:

```r
raw <- readRDS("data/processed/analysis_raw.rds")
split <- readRDS("data/processed/split.rds")
dictionary <- read.csv("data/processed/feature_dictionary.csv")
saveRDS(raw[split$test, dictionary$feature, drop=FALSE], "features.rds")
```

```bash
make predict INPUT=features.rds OUTPUT=predictions.csv
```

`predicted_class`, `ad_score`, `score_type`, `model` and `objective` identify the decision and its origin. SVM margins are uncalibrated; a correction output explicitly identifies its Elastic Net component score. The selected manifest checks configuration, data/schema and artifact identities. Failed scoring does not replace an existing prediction file.

The optional compatibility command `make predict-legacy INPUT=features.rds OUTPUT=legacy.csv` uses the original accuracy-oriented correction interface. It requires the legacy training stage, enabled by `run_correction = TRUE`. It is retained for comparison and does not override the CV selection.

## Public snapshot and checks

`make publish-results` requires a completed validated benchmark. It replays the selected serialized predictor, checks input identities, stages both CSVs and four figures, verifies their integrity, and replaces the public snapshot and README tables together. Unexpected files or symlinks in `results/` are rejected instead of discarded. No timestamps enter the exported tables.

```bash
python3 scripts/publish_results.py --check
```

This lightweight check needs only the checkout: it validates metric/count relationships, configuration/source signatures, figure hashes and the README tables without training data. The complete `make check` also verifies original data, nested folds, serialization, prediction and result export using isolated synthetic fixtures. Tests must not change the public snapshot of the real project.

GitHub Actions defines automatic checks and a manual `full-analysis.yml` workflow, both using Ubuntu 24.04, R 4.6.2 and the lockfile. A successful hosted full-analysis run is required before marking cross-platform release validation complete. Local macOS checks do not establish Ubuntu compatibility, and other R versions remain unverified. Run the manual workflow from the repository's Actions tab after pushing. The public dataset needs no credentials.

The historical test has already influenced development. Keep its published results fixed; use a newly collected, separately held-out dataset for independent evaluation. Comment cleanup may change source fingerprints, but it must not change model settings, metrics or figures.

## File policy

Commit source, concise Markdown documentation and only the six curated files under `results/`. Raw/processed data, trained binaries, intermediate matrices, local environments, caches and old distributions are ignored. The source-code license remains an owner decision; the dataset's CC BY 4.0 attribution is separate.

Before publishing, review author and committer metadata with `git log --format=fuller`. Removing identifiers from current files does not remove them from earlier commits.
